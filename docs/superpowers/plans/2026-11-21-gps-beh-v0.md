# GPS záznam běhu v0 – implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Uživatel v appce zmáčkne Start, běží, zmáčkne Stop, uvidí souhrn s mapou a běh se uloží do jeho dat.

**Architecture:** Výpočty (filtr, vzdálenost, tempo, mezičasy) jsou čisté funkce v `mobile/my-app/lib/beh/vypocty.ts` s testy ve Vitestu. Záznam polohy a stopky jsou v hooku `lib/beh/zaznam.ts`, obrazovky jen zobrazují. Po Stop se běh i body pošlou jedním požadavkem na `POST /api/runs`, který je uloží v transakci; mapa v detailu běhu si body načte z `GET /api/runs/points`.

**Tech Stack:** Expo SDK 58 (Expo Go), expo-location, expo-keep-awake, react-native-maps, expo-crypto, Vitest; Next.js 16 API, Zod 4, PostgreSQL.

**Spec:** `docs/superpowers/specs/2026-11-21-gps-beh-v0-design.md`

## Global Constraints

- Vše v0 musí běžet v **Expo Go** – žádná knihovna, která vyžaduje vlastní build.
- Filtr: přesnost horší než **20 m** → bod zahodit; rychlost nad **10 m/s** od posledního dobrého bodu → zahodit; čas, který není novější než předchozí → zahodit.
- Aktuální tempo: okno **30 s**; pod **20 m** v okně → zobrazit `--:--`.
- Tempo se ukládá a předává v **sekundách na km**, zobrazuje jako `m:ss`.
- Poloměr Země pro Haversine: **6 371 000 m**.
- Backend: nejvýš **20 000 bodů** na běh; uložení běhu a bodů v **jedné transakci**; `external_id` = UUID z telefonu, opakované odeslání nevytvoří druhý běh.
- Body trasy jen pro vlastníka (cizí běh → **404**), nikdy v logu.
- Commit až po hotové v0, bez řádku „Co-Authored-By".

### Task 8: `POST /api/runs` (uložení v transakci)

**Files:** Create `web/muj-next-app/app/api/runs/route.ts`

**Interfaces:**
- Consumes: `getCurrentUser()` z `@/lib/session`, `pool` z `@/lib/db`, `ulozBehSchema` z `@/lib/runs`, `prepocitatMetriky` z `@/lib/metrics`
- Produces: `POST /api/runs` → `201 { ok: true, activity_id: number }`; opakované odeslání stejného `external_id` → `200 { ok: true, activity_id: number, uz_ulozeno: true }`; 400 / 401

Postup funkce `POST`:
1. `getCurrentUser()`, jinak 401.
2. Tělo přes `try/catch` kolem `request.json()` (rozbitý JSON → 400, jako v registraci), pak `ulozBehSchema.safeParse` → chyba 400 s první zprávou.
3. `const client = await pool.connect()` a uvnitř `try { BEGIN … COMMIT } catch { ROLLBACK; throw } finally { client.release() }`.
4. Vložit běh do `activities`: `source = 'app'`, `external_id`, `sport_type = 'run'`, `name = 'Běh'`, `started_at`, `elapsed_time_s`, `moving_time_s`, `distance_m`, `avg_speed_ms = distance_m / moving_time_s` (jen když `moving_time_s > 0`), s `ON CONFLICT (user_id, source, external_id) DO NOTHING RETURNING id`.
5. Když `RETURNING` nic nevrátí (běh už existuje): dohledat jeho `id` pro tohoto uživatele, `COMMIT`, vrátit 200 s `uz_ulozeno: true`.
6. Body vložit **jedním dotazem** přes `unnest` (jinak by to bylo 3 600 dotazů):

```sql
INSERT INTO activity_points (activity_id, seq, recorded_at, lat, lon, accuracy_m, segment)
SELECT $1, seq, to_timestamp(cas_ms / 1000.0), lat, lon, presnost, segment
FROM unnest($2::int[], $3::float8[], $4::float8[], $5::float8[], $6::float8[], $7::int[])
     AS t(seq, cas_ms, lat, lon, presnost, segment)
```
